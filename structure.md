# Pinebook Pro Keyboard Firmware — структура проекта и анализ проблемы

> Анализ механизма прошивки и причин рассогласования физических и отображаемых клавиш.

---

## 1. Контроллер и архитектура прошивки

Контроллер клавиатуры Pinebook Pro — **SH68F83** (Sinowealth, ядро 8051).
Прошивка `firmware/default_ansi.hex`, которую шьёт пользователь, собирается из **двух частей** (пользователь был прав насчёт «дефолтной части, сшивающейся с компилируемой»).

### 1.1. Базовая (заводская) часть — `firmware/fw_ansi.hex`

Это дизассемблированная оригинальная прошивка производителя (см. `firmware/dis51/fw_ansi.a51`).
В ней живёт весь «движок» прошивки:

- USB-стек и дескрипторы (VID/PID, строки, HID-дескрипторы клавиатуры и тачпада);
- сканирование матрицы клавиш (функции `L0149`, `L0184`, `L0188`, `L0191` в `src/main.c`);
- парсер keymap (`L0145`, `L0168`, `L0170`, `L0172`);
- I2C-общение с тачпадом и EEPROM kill-переключателей (`L0136`–`L0139`, `L0201`);
- обработка Fn-слоёв и медиа/спецклавиш;
- управление kill-переключателями MIC/WIFI/CAM (`L0143`).

Это «источник истины» — сама по себе она не правится.

### 1.2. Компилируемая надстройка — `firmware/src/`

- `revised.c` — общие патчи базовой прошивки: USB-дескрипторы, имена производителя/продукта, HID тачпада, логика F10–F12, исправление стрелок/numlock и т. п.
- `keymaps/<name>.c` — конкретная раскладка (по умолчанию `default_ansi.c`).

### 1.3. Сборка (`firmware/src/Makefile`)

```
sdcc  revised.rel + keymaps/<name>.rel   ->  revised_<name>.ihx   (код размещается по адресу 0x3000)
srec_cat  fw_ansi.hex  +  revised_<name>.ihx  ->  <name>.hex      (overlay: перезаписывает нужные адреса в базовой прошивке)
```

Компилятор выдаёт «заплатку», которая накладывается поверх `fw_ansi.hex`, заменяя только определённые байты.
Готовый `.hex` шьётся через:

```
sudo ./updater flash-kb firmware/default_ansi.hex
```

## 2. Как задаётся раскладка

В `keymaps/default_ansi.c` массив `keymap[]` размещён по фиксированному адресу `0x0815` и заполняется макросом `KEYMAP_ANSI(...)` из `include/keymap.h`.

Этот макрос разворачивает **логические имена** клавиш (`esc, f1..f12, grv, 1..0, q..p, a..l, z..sls, …`) в **плоский массив ячеек физической матрицы** (18 рядов × 8 колонок = 144 ячейки):

```c
#define KEYMAP_ANSI( \
    esc, f1, f2, f3, f4, f5, f6, f7, f8, f9, f10, f11, f12,          \
    grv,  n1, n2, n3, n4, n5, n6, n7, n8, n9, n0, min, eql, bkp,     \
    tab,   q,  w,  e,  r,  t,  y,  u,  i,  o,  p,  lbr, rbr, bsl,    \
    cap,    a,  s,  d,  f,  g,  h,  j,  k,  l,  sem, quo, ent,       \
    lsf,     z,  x,  c,  v,  b,  n,  m, com, dot, sls, rsf, up,      \
    lct, fn, pi, lal,         spc,           ral, rct, lef, dn, rht) \
    { \
        NK,  NK,  NK,  NK,  NK,  NK,  NK,  pi,  \
        ral, NK,  NK,  NK,  NK,  NK,  NK,  lal, \
        ...   // 18 строк по 8 колонок
    }
```

Иными словами, макрос **жёстко кодирует соответствие «логическая клавиша ↔ физическая ячейка матрицы (ряд/колонка на FPC-шлейфе)»**.

Хелперы для задания типа/кода клавиши (см. `include/keymap.h`):

| Хелпер  | Назначение                                              |
|---------|---------------------------------------------------------|
| `R(n)`  | обычная клавиша, к `n` добавляется префикс `KC_`        |
| `M(n)`  | модификатор (биты USB: `LCTL=0x01`, `LSFT=0x02`, …)     |
| `F(n)`  | функциональная клавиша (Fn-слой)                        |
| `FS(n)` |lookup в массиве `fns_special[]`                          |
| `FR(n)` | lookup в массиве `fns_regular[]`                        |
| `FK(n)` | lookup в массиве `fns_keypad[]`                         |

Fn-массивы (`fns_special`, `fns_regular`, `fns_keypad`) задают действие клавиш при нажатой Fn; переставлять их местами нельзя — код рассчитывает на их порядок. Они размещаются в свободной области кода `0x3000`.

## 3. Суть проблемы (рассогласование клавиш)

Пользователь прошил `firmware/default_ansi.hex` и зафиксировал в `firmware/src/remap.txt` расхождение «физически нажал → что отобразилось».

Примеры из файла:

```
2 G      <- физическая «2» выдаёт «G»
5 2      <- физическая «5» выдаёт «2»
W V      <- физическая «W» выдаёт «V»
T 3
P Y
S R
...
```

**Интерпретация:** ячейка матрицы, которую опрашивает физическая клавиша X, в макросе `KEYMAP_ANSI` подписана как f(X).
То есть физическое расположение клавиш на шлейфе у данной клавиатуры **не совпадает с тем, что зашито в макрос `KEYMAP_ANSI`** (видимо, другая ревизия платы / иная разводка FPC).

Лечится это **перестройкой таблицы соответствия внутри макроса** `KEYMAP_ANSI` в `include/keymap.h`, а не правкой USB-части.

## 4. Почему исходники пока не менялись

Чтобы обратить перестановку и пересобрать матрицу в макросе **однозначно**, нужна полная и непротиворечивая таблица «нажал → отобразилось» для всех клавиш. Текущий `remap.txt`:

1. **Противоречив.** Есть строки `P Y` и `K Y` — две разные физические клавиши якобы выдают одну и ту же `Y`. При матричном опросе одна клавиша = одна ячейка, так быть не может — одна из строк, скорее всего, с ошибкой.
2. **Неполон.** Многие клавиши не проверены: `G`, `Y`, `U`, `I`, `O` (как источник), `H`, `N`, `B`, `Q`, `A`, `R`, `E`, цифры `1/3/9`, `F1–F12`, стрелки, модификаторы. Без них обратить перестановку нельзя: части перестановки связаны циклами (например, `5→2→G→?`), и поменяв часть, мы почти гарантированно сломаем соседние непроверенные клавиши.

Поэтому для корректной правки нужна **полная таблица** для всех клавиш ряду за рядом:

- ряд F1–F12 + Esc
- цифровой ряд: `` ` 1 2 3 4 5 6 7 8 9 0 - = Backspace ``
- ряд: `Tab Q W E R T Y U I O P [ ] \`
- домашний ряд: `Caps A S D F G H J K L ; ' Enter`
- ряд: `Shift Z X C V B N M , . / Shift`
- нижний: `Ctrl Fn Super Alt Space Alt Ctrl` + стрелки Вверх/Вниз/Влево/Вправо
- отдельные: клавиша-лупа, Power

С полной картиной матрицу в макросе `KEYMAP_ANSI` можно перестроить так, чтобы отображаемые клавиши совпали с физическими.

## 5. План действий (после получения полной карты)

1. По полной таблице «физически → отображённое» построить обратную перестановку.
2. В `include/keymap.h` пересобрать тело макроса `KEYMAP_ANSI` так, чтобы каждая ячейка матрицы указывала на правильное логическое имя.
3. При необходимости поправить только затронутые позиции в `keymaps/default_ansi.c` (хелперы `R()/FS()/FR()/FK()` обычно остаются те же — меняется лишь раскладка по ячейкам).
4. Не трогать `revised.c`, USB-дескрипторы и адреса Fn-массивов — они к матрице отношения не имеют.
5. Пользователь сам пересоберёт (`make -C firmware/src default_ansi`) и прошьёт, затем сообщит промежуточный результат.
