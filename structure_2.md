# Pinebook Pro Keyboard Firmware — техническое описание проекта

> Быстрый «онбординг-гайд» для разработчика: где что лежит, как править раскладку, как собирать/прошивать, и какие неочевидные подводные камни есть в этой кодовой базе.

---

## 0. Краткая шпаргалка (TL;DR)

- **Железо:** клавиатурный контроллер **SH68F83** (Sinowealth, ядро 8051). Внешний USB-HID устройство к хосту, I²C-мастер к тачпаду и EEPROM kill-переключателей.
- **Прошивка состоит из 2 слоёв:**
  1. Заводская `firmware/fw_ansi.hex` (`fw_iso.hex` для ISO) — дизассемблирована в `firmware/dis51/*.a51`, псевдокод в `firmware/src/main.c`. **Не правится напрямую.**
  2. Компилируемая «заплатка» из `firmware/src/` (`revised.c` + `keymaps/<name>.c`), накладываемая оверлеем поверх заводской прошивки.
- **Где живёт раскладка:** `firmware/src/include/keymap.h` — макрос `KEYMAP_ANSI(...)`/`KEYMAP_ISO(...)`, который разворачивает имена клавиш в 18×8 = 144 ячейки физической матрицы. **Именно этот файл правится под конкретную ревизию FPC-шлейфа клавиатуры.**
- **Конкретные значения клавиш** (HID-коды) задаются в `firmware/src/keymaps/<name>.c` через хелперы `R()/M()/F()/FS()/FR()/FK()`.
- **Сборка:** `make -C firmware/src <name>` (например, `default_ansi`) → результат кладётся в `firmware/<name>.hex`.
- **Прошивка:** `sudo ./updater flash-kb firmware/<name>.hex`.
- **Предварительные шаги** (один раз для новой машины): `sudo ./updater step-1`, poweroff, `sudo ./updater step-2 ansi`, poweroff. После этого можно бесконечно рефлэшить через `flash-kb`.

## 2. Как устроена прошивка (двухслойная архитектура)

Заводской `.hex` содержит весь «движок» прошивки: USB-стек, скан матрицы клавиш, парсер keymap, I²C-общение с тачпадом/EEPROM, обработку Fn-слоёв и kill-переключателей. Мы **не трогаем** этот бинарник напрямую.

Компилируемая надстройка (`firmware/src/`) собирается утилитой **sdcc** (Small Device C Compiler, целевая архитектура 8051) и **srecord** (`srec_cat`) в маленький `.ihx`, который размещается начиная с адреса `0x3000`. Затем этот `.ihx` накладывается как оверлей на `fw_ansi.hex` через `srec_cat`, перезаписывая заданные байты (конкретный keymap по адресу `0x0815`, строковые USB-дескрипторы, фиксы F10–F12, адреса Fn-массивов). Результат — `<name>.hex`, готовый к прошивке.

### 2.1. Makefile (`firmware/src/Makefile`)

```bash
# Сборка конкретной раскладки:
make -C firmware/src default_ansi
#       ↑ означает «скомпилировать keymaps/default_ansi.c»
#       результат: firmware/default_ansi.hex
```

Для сборки нужны пакеты:
```bash
sudo apt-get install sdcc srecord   # Debian/Ubuntu
# или эквиваленты в другом дистрибутиве
```

### 2.2. Утилита прошивки `./updater` (корень репозитория)

Собирается из `updater.c` + `usb_*.c` через `make` в корне репозитория. Зависимости: `libusb-1.0-0-dev`, `xxd`.

Команды:

| Команда | Что делает |
|---|---|
| `./updater step-1` | Шьёт `fw_tp_update.hex` — переводит клаву в режим программатора тачпада. **После этого надо poweroff.** |
| `./updater step-2 ansi\|iso` | Шьёт тачпад (`tpfw.bin`) и затем клаву (`fw_ansi.hex` или `fw_iso.hex`). **После этого надо poweroff.** |
| `./updater flash-kb <file.hex>` | Шьёт **произвольный** `.hex` в клавиатуру (главная команда для итераций). Перепрошивка мгновенная, poweroff не требуется. |
| `./updater flash-tp` | Перешивает только тачпад. |
| `./updater flash-kb-ansi` / `flash-kb-iso` | Шьёт встроенные `fw_ansi.hex`/`fw_iso.hex`. |
| `./updater convert` | Декодирует hex в bin (служебное). |

**Типичный рабочий цикл** (после первого `step-1` + `step-2`):

```bash
make -C firmware/src default_ansi
sudo ./updater flash-kb firmware/default_ansi.hex
```

## 3. Анатомия раскладки (самое важное для правок)

### 3.1. Физическая матрица

Клавиатура опрашивается как матрица **18 рядов × 8 колонок = 144 ячейки** (на практике используется ~90 клавиш). Аппаратный скан написан в заводской части (`L0149`, `L0184`, `L0188`, `L0191` в `firmware/src/main.c`). При замыкании ячейки (ряд R, колонка C) движок читает 2-байтный код из таблицы `keymap[]` по смещению `R*8 + C` и интерпретирует его согласно типу клавиши.

> **⚠️ Тонкость ревизии платы:** на некоторых Pinebook Pro матрица «транспонирована» относительно того, что ожидает движок. То есть физический (R, C) в шлейфе соответствует байту `keymap[C*8 + R]`, а не `keymap[R*8 + C]`. В текущей правке `keymap.h` используется именно **транспонированная** запись: макрос объявлен как 18 строк по 8 колонок, но фактически `matrix[R][C]` → `macro[C][R]`. См. раздел 5.

### 3.2. Макрос `KEYMAP_ANSI` (`firmware/src/include/keymap.h`)

```c
#define KEYMAP_ANSI( \
    esc, f1, f2, f3, f4, f5, f6, f7, f8, f9, f10, f11, f12,          \
    grv,  n1, n2, n3, n4, n5, n6, n7, n8, n9, n0, min, eql, bkp,     \
    tab,   q,  w,  e,  r,  t,  y,  u,  i,  o,  p,  lbr, rbr, bsl,    \
    cap,    a,  s,  d,  f,  g,  h,  j,  k,  l,  sem, quo, ent,       \
    lsf,     z,  x,  c,  v,  b,  n,  m, com, dot, sls, rsf, up,      \
    lct, fn, pi, lal,         spc,           ral, rct, lef, dn, rht) \
    { \
        /*       R0   R1   R2   R3   R4   R5   R6   R7 */ \
        /*C0*/  NK,  NK,  NK,  rct, NK,  lct, NK,  NK,  \
        /*C1*/  q,   n1,  z,   a,   grv, tab, esc, cap,  \
        ...                                                     \
        /*C17*/ NK,  NK,  NK,  NK,  NK,  NK,  NK,  NK    \
    }
```

В **аргументах** макроса перечислены **логические имена** всех клавиш ANSI-раскладки (это «символьные заполнители»). В **теле** макроса эти имена расставлены по 18 строкам (= «колонкам» матрицы, см. ⚠️ выше) по 8 ячеек. Каждая позиция жёстко задаёт: «в этой ячейке матрицы живёт вот эта логическая клавиша».

Макрос **только фиксирует геометрию** — он не знает HID-коды. Конкретный HID-код для каждой клавиши подставляется в `keymaps/<name>.c`, где аргументы макроса заполняются хелперами `R(Q)`, `M(LSFT)`, `F(0)`, `FS(3)`, `FR(7)`, `FK(5)` и т. д.

### 3.3. Хелперы для типов клавиш (`include/keymap.h`)

| Хелпер  | Назначение | Пример |
|---|---|---|
| `R(n)`  | Обычная клавиша. К `n` добавляется префикс `KC_`. | `R(A)` → HID `KC_A = 0x04` |
| `M(n)`  | Модификатор. `n` — биты USB: `LCTL=0x01`, `LSFT=0x02`, `LALT=0x04`, `LGUI=0x08`, `RCTL=0x10`, `RSFT=0x20`, `RALT=0x40`, `RGUI=0x80`. | `M(LSFT)` → левый Shift |
| `F(n)`  | Fn-клавиша. Пока реализован только `F(0)` — включает Fn-слой. | `F(0)` |
| `FS(n)` | Fn-функция из массива `fns_special[]`. | `FS(0)` → F1 → Brightness Up |
| `FR(n)` | Fn-функция из массива `fns_regular[]`. | `FR(6)` → Up → PgUp |
| `FK(n)` | Fn-функция из массива `fns_keypad[]`. | `FK(0)` → M → Numpad 0 |

Полный список HID-кодов `KC_*` — в `firmware/src/include/keycodes.h`.

### 3.4. Fn-массивы (`keymaps/<name>.c`)

Три массива задают «что делает клавиша при зажатой Fn»:

```c
__code uint16_t fns_special[] = { ... };  // спец: яркость, звук, тоггл тачпада
__code uint16_t fns_regular[]  = { ... };  // стрелки → Home/PgUp, F-ряды → Ins/PScr...
__code uint16_t fns_keypad[]   = { ... };  // буквенный блок → numpad
```

Каждый элемент: `REG_FN(<базовый код>, <код под Fn>)`.

**⚠️ Важные правила:**
1. Эти массивы **нельзя переставлять** местами — движок завязан на их порядок в памяти.
2. Они размещаются в свободной области `0x3000` (макрос `STARTING_ADDR`).
3. Адреса массивов вычисляются на этапе компиляции и вручную прописываются в фиксированные ячейки (`0x18E3`, `0x18C0`, `0x06D5`, `0x079D` и т. д.) через `__code __at`. **Не редактируйте эти адреса без необходимости.**

## 4. Рабочие файлы для отладки раскладки

### 4.1. `map.txt` (корень репозитория)

Содержит **оцифровку документации производителя** + текущее состояние макроса. Структура:

```
1. Клавиши:             ← список имён клавиш макроса KEYMAP_ANSI
2. Номера ячеек:        ← нумерация производителя (не всегда надёжна!)
3. Матрица клавиш:      ← таблица R0..R7 × C0..C15 с номерами ячеек
4. Сам макрос           ← копия тела KEYMAP_ANSI на момент составления
```

**Известные несоответствия в нумерации производителя:**
- Цифры сдвинуты на 1 позицию (в документации n2 — это на самом деле n3, и т. д.).
- Встречаются дубли: например, ячейка 43 указана и как `c`, и как `ent` (на самом деле `c` = ячейка 48).
- Надёжная часть — **матрица R×C** (блок 3). Номера ячеек (блок 2) использовать с осторожностью, сверяясь с `remap.txt`.

### 4.2. `firmware/src/remap.txt`

**Живой журнал тестирования.** Здесь пользователь записывает, что физически нажал → что отобразилось на экране. Формат зависит от этапа:

- Этап 1 (полная рассинхронизация): `2 G` — нажал «2», получил «G».
- Этап 2 (после частичной правки): `1 1`, `2 ничего`, `3 2`, ... — сдвиг цифр.
- Этап 3 (почти готово): `все буквы на своих местах`, `ctrl это ctrl`, но `вниз → вправо`.

**По этим данным строится обратная перестановка:** если физическая кнопка X выдаёт Y, значит ячейка матрицы, к которой подключена кнопка X, в макросе подписана как Y. Чтобы исправить — нужно в позицию ячейки X поставить имя X.

## 5. Как править раскладку под новую ревизию клавиатуры

### 5.1. Диагностика

1. Прошить `default_ansi.hex`.
2. Занести в `firmware/src/remap.txt` все несоответствия «нажал → получил».
3. Сопоставить с матрицей в `map.txt` — убедиться, что ячейка каждой сломанной клавиши определена.

### 5.2. Правка макроса `KEYMAP_ANSI`

**Файл:** `firmware/src/include/keymap.h`.

Каждая строка тела макроса — это «колонка» матрицы (C0..C17), позиции внутри строки — «ряды» (R0..R7). То есть:

```c
/*C1*/  q,   n1,  z,   a,   grv, tab, esc, cap,  \
//      R0   R1   R2   R3   R4   R5   R6   R7
```

…означает: `keymap[C1][R0] = q`, `keymap[C1][R1] = n1` и т. д. (транспонированная запись).

**Алгоритм правки:**
1. Для каждой сломанной клавиши найти в `map.txt` её координаты (R, C) по матрице производителя.
2. В теле макроса в строке с номером `C` на позицию `R` поставить соответствующее имя.
3. Если имя уже стоит в другой позиции (дубль) — оттуда его убрать (заменить на `NK`), иначе клавиша будет задвоена.
4. Непроверенные эмпирически клавиши заполняются по документации, но при первой же возможности проверяются через `remap.txt`.

### 5.3. Сборка и прошивка

```bash
make -C firmware/src default_ansi
sudo ./updater flash-kb firmware/default_ansi.hex
```

Затем повторить цикл «нажал → записал в `remap.txt` → поправил макрос» до полного схождения.

### 5.4. Чего **НЕЛЬЗЯ** делать

- Не править `firmware/fw_ansi.hex` и `firmware/dis51/*.a51` — это источник истины.
- Не трогать `revised.c` — там лежат общие для всех раскладок патчи USB/HID/Fn, к матрице отношения не имеющие.
- Не менять адреса Fn-массивов (`__code __at (0x18E3)`, `0x18C0`, `0x06D5`, `0x079D` и т. д.) — они захардкожены в заводском коде.
- Не переупорядочивать `fns_special`, `fns_regular`, `fns_keypad` — движок ждёт их именно в таком порядке.
- Не вставлять обычные функции/переменные в `keymaps/*.c` — компилятор sdcc размещает код «как есть», и обычные символы не лягут по нужным адресам. Допустимы только `__code __at (...)` и `__code <array>[] = {...}`.

## 6. Адреса в прошивке (шпаргалка)

| Адрес | Что там лежит |
|---|---|
| `0x009B–0x00B7` | USB-строка производителя (патч в `revised.c`: «Byterg») |
| `0x00BC–0x00D5` | USB-строка продукта («Byterg Laptop») |
| `0x007E–0x008F` | USB-строка серийного номера («ANSI 0.1» в `default_ansi.c`) |
| `0x0109` | `bcdDevice` (0.01) |
| `0x010D` | индекс серийной строки → 0xFF |
| `0x018E3, 0x018C0, 0x06D5, 0x079D` | указатели на старты Fn-массивов (DPL/DPH) |
| `0x0620, 0x0658, 0x0690` | обработчики F10/F11/F12 (патч → `LJMP NEW` в `revised.c`) |
| `0x0815` | **начало массива `keymap[]`** (288 байт = 144 ячейки × 2 байта) |
| `0x0935` | конец keymap / устаревший адрес `fns_special` |
| `0x2224, 0x222C, 0x223E` | lookup-таблицы скан матрицы (в заводском коде) |
| `0x3000` | начало Fn-массивов (`STARTING_ADDR`), свободная область до `0x37FB` |

## 7. Обратная инженерия заводской прошивки

- **Дизассемблер:** [`dis51`](https://github.com/rayducmoore/dis51) применён к `fw_ansi.hex` → `firmware/dis51/fw_ansi.a51`.
- **Псевдокод:** `firmware/src/main.c` — не компилируемый C, а человекочитаемая расшифровка ключевых функций:
  - `L0149` / `L0184` / `L0188` / `L0191` — скан матрицы клавиш.
  - `L0145` / `L0168` / `L0170` / `L0172` — парсер keymap.
  - `L0136` / `L0137` / `L0138` / `L0139` — I²C-примитивы (start/send/stop/read).
  - `L0143` — управление kill-переключателями MIC/WIFI/CAM + отправка USB endpoint 1.
  - `L0144` — отправка USB endpoint 2.
  - `L0201` — обработка данных тачпада.
  - `L0140` — главный цикл.

Документация по контроллеру: `firmware/docs/sinowealth-sh68f83-datasheet-v2.pdf`.

## 8. Типичные проблемы и их диагностика

| Симптом | Причина | Куда смотреть |
|---|---|---|
| Клавиша выдаёт не ту букву | Ячейка матрицы в макросе подписана другим именем | `keymap.h`, `map.txt`, `remap.txt` |
| Клавиша ничего не выдаёт | Ячейка матрицы пуста (`NK`) или имя стоит не в той позиции | `keymap.h` — проверить (R, C) |
| Две физические клавиши выдают одно и то же | Имя клавиши случайно продублировано в двух ячейках | `keymap.h` — поиск дубликатов |
| Стрелки/модификаторы перепутаны | Нижний ряд размечен по битной нумерации, а не по матрице R×C | Блок 3 в `map.txt`, C13–C15 |
| Fn-функции не работают | Сдвинуты адреса Fn-массивов или нарушен их порядок | `keymaps/<name>.c`, адреса `0x18E3` и т. д. |
| После прошивки клава не отвечает | Не прошёлся `step-2` / завис boot mode | Power cycle; затем `step-1` + `step-2` заново |
